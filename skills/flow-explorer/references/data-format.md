# 데이터 형식

탐색기 하나는 **데이터 폴더** 하나에서 만들어집니다. 엔진(`engine/explorer.html`)은 모든 프로젝트가 같이 쓰고, 프로젝트마다 다른 것은 데이터 폴더에만 둡니다.

```text
<데이터 폴더>/
├── data.json        제목, 부제, 넣을 JS 파일 목록
├── topology.js      구성도(노드·그룹·선), 로고, 방화벽 규칙, 화면 설정
├── <흐름>.js         단계 목록과 흐름(SC). 여러 파일로 나눠도 됨
├── <구간>.js         흐름을 4~6개 구간으로 묶는 범위
├── <패킷>.js         단계마다 실제로 오가는 패킷 내용
├── ja.js            (선택) 일본어 번역. 다른 언어도 같은 방식
├── theme.css        (선택) 색 바꾸기. 아래 "색"
└── icons/           브랜드 로고(svg·png·webp). 파일 이름이 로고 이름
```

빌드: `python build.py <데이터 폴더> <출력 HTML>`. 결과는 글꼴·로고·데이터가 모두 들어간 HTML 파일 하나입니다.

데이터 파일은 값을 선언만 합니다. 묶음 제목, 구간, 단계별 구간 번호는 엔진이 계산합니다.

## data.json

```json
{
  "title": "탐색기 제목 (브라우저 탭과 왼쪽 위)",
  "subtitle": "제목 아래 한 줄",
  "langs": ["ko", "ja"],
  "topology": "topology.js",
  "scripts": ["flows.js", "groups.js", "packets.js", "ja.js"]
}
```

`scripts`는 적은 순서대로 이어 붙입니다. 뒤 파일은 앞 파일의 변수(`S`, `SC`, `PH` 등)를 쓸 수 있습니다.
흐름 목록 `SC`는 데이터가 꼭 선언합니다. 엔진이 미리 선언해 두는 이름(`TOPO`, `LOGO`, `FWR`, `META`, `TR`, `IN`, `PH`, `GR`, `PKT`)은 `var`로 선언하거나 값만 넣습니다. `const`·`let`으로 다시 선언하면 엔진의 선언과 부딪혀 열리지 않습니다.

`langs`는 화면 언어 목록입니다(없으면 `["ko"]`). 첫째가 데이터를 쓴 원문 언어이고, 둘 이상이면 머리 오른쪽에 언어 메뉴가 나옵니다. 아래 "언어"를 보세요.

`css`(선택)는 엔진 CSS 뒤에 넣을 CSS 파일 목록입니다. 아래 "색"을 보세요.

## topology.js

엔진이 미리 `var TOPO = {}, LOGO = {}, FWR = {}, META = {}, TR = {}, IN = "같은 VM";`을 선언해 둡니다. topology.js는 이 값들을 채웁니다.

### TOPO.<구성도 이름>

흐름마다 `tp` 값으로 구성도를 고릅니다(아래 SC). 구성도는 여러 개를 둘 수 있습니다.

```js
TOPO.web = { vb:{ x:0, y:0, w:960, h:640 }, col:140 };   // vb: 구성도 전체 viewBox, col: 시퀀스 화면의 열 너비
TOPO.web.N = {                                            // 노드
  browser: { x:120, y:80, nm:"사용자 브라우저", rl:"Chrome" },
  proxy:   { x:420, y:260, nm:"nginx", rl:":443", full:"nginx (리버스 프록시)", sm:0 },
  vm:      { grp:"g_vm", nm:"앱 서버 VM" }                 // 그룹 자체를 노드로 쓸 때(시퀀스의 참여자)
};
TOPO.web.G = [                                            // 그룹 상자
  { id:"g_vm", x:300, y:180, w:500, h:360, cls:"b", t:"앱 서버 VM" }
];
TOPO.web.L = {                                            // 선(구성도에 그리는 길). p는 꺾인 점 목록
  br_px: { a:"browser", b:"proxy", p:[[120,160],[120,260],[384,260]] },
  px_db: { a:"proxy", b:"db", p:[[420,340],[420,420]], bg:1 }   // bg:1 = 번호 없는 배경 연결(점선)
};
TOPO.web.order = ["browser", "proxy", "app", "db"];       // 시퀀스 화면의 열 순서
TOPO.web.sr = { browser:"사용자", proxy:":443" };         // 시퀀스 머리의 짧은 설명
```

| 노드 속성 | 뜻 |
|---|---|
| `x`, `y` | 아이콘 가운데 좌표(구성도 좌표) |
| `nm` | 이름(아이콘 아래 큰 글씨) |
| `rl` | 역할(이름 아래 작은 글씨) |
| `full` | 단계 설명에 쓰는 긴 이름. 없으면 `nm` |
| `al` | 목록과 말풍선에 쓰는 짧은 이름(아래 별칭 표로 넣어도 됨) |
| `sn` | 시퀀스 머리에 쓰는 이름. 없으면 `nm` |
| `sm` | 1이면 작은 아이콘(외부 서비스 등) |
| `grp` | 그룹 상자 id. 노드 대신 그룹 상자가 강조됨 |
| `iso` | `[아이콘 종류, 표식]`. 아래 표 |
| `brand` | 미니 로고 이름(`LOGO`의 키). 우측 상단에 자동 배치 |

| 그룹 `cls` | 모양 |
|---|---|
| `n` | 바깥 영역(클라우드·망). 바탕 없이 점선 테두리 |
| `b` | 서버·VM·프로세스. 실선 테두리와 옅은 바탕 |
| `d` | 따로 떨어진 시스템(예: 기존 DB 서버). 점선 테두리와 불투명한 바탕(뒤로 지나는 선을 가림) |

아이콘 종류(`iso[0]`): `rack`, `flat`, `db`, `laptop`, `doc`, `shield`, `funnel`, `gauge`, `archive`, `registry`, `padlock`, `toolbox`, `layers`
표식(`iso[1]`, 선택): `key`, `lock`, `sparkle`, `code`, `arrows`, `branch`, `building`, `plug`, `check`, `bang`, `shield`, `gear`, `person`, `window`, `list`, `layers`, `down`, `gauge`, `keyhole`

표식은 `rack`·`flat`·`db`(윗면), `laptop`(화면), `shield`(방패 안), `archive`(옆면, 없으면 `down`)에만 그려집니다. `doc`은 `gear`만 그리고, 나머지 아이콘은 정해진 무늬만 있어 표식을 쓰지 않습니다.

노드가 많으면 별칭·아이콘·로고를 표로 모아 두고 반복문으로 노드에 넣어도 됩니다. 엔진은 결과로 생긴 노드 속성만 봅니다.

### LOGO

```js
LOGO = { nginx:"%%ICON_nginx%%", postgresql:"%%ICON_postgresql%%" };
```

`%%ICON_<이름>%%`은 빌드가 `icons/<이름>.svg|png|webp`의 data URI로 바꿉니다. 로고는 공식 마크만 쓰고 색을 바꾸지 않습니다.

### FWR (방화벽 규칙)

단계의 `fw`에 규칙 번호를 쓰면 단계 설명에 여는 통신과 이유가 나옵니다.

```js
FWR = {
  F1: { r:"인터넷 → 앱 서버 공인 IP · TCP 443", sh:"인터넷 → 443", d:"사용자 브라우저가 HTTPS로 들어오는 길입니다." }
};
```

`r`: 여는 통신, `sh`: 아래 막대용 한 줄 요약, `d`: 왜 여는지.

### META (화면 설정)

```js
META = { key:"my-project", start:0, filters:[["all","전체"],["web","웹"]], fwNet:"사용자와 외부 서비스 사이의 인터넷 통신입니다." };
```

| 키 | 뜻 |
|---|---|
| `key` | 본 기록(어디까지 봤는지)을 브라우저에 저장할 이름. 탐색기마다 다르게 |
| `start` | 처음 고를 흐름 번호(SC 순서) |
| `filters` | 왼쪽 필터 탭 `[tp 값, 이름]`. 없으면 흐름의 `tp` 값으로 만듦 |
| `fwNet` | `fw:"인터넷"`인 단계의 설명 |
| `fwIn` | `fw:IN`(같은 VM)인 단계의 설명. 없으면 "같은 VM 안의 통신이라 VM 방화벽을 지나지 않습니다." |
| `inproc` | 같은 프로세스 안의 호출로 볼 패킷 프로토콜 목록. 없으면 `["JVM", "JDBC"]` |

필터 탭은 묶음이 둘 이상일 때만 보입니다(`전체`와 구성도 하나뿐이면 감춤). 탭이 칸보다 넓으면(묶음이 많거나 이름이 긴 언어) 흐름 수 배지를 숨겨 한 줄에 맞춥니다. 이름은 짧게 씁니다(예: `웹`, `배포`).

## 단계와 흐름

```js
var S = [
  { n:1, ph:"A", k:"q", f:"browser", t:"proxy", l:"br_px", lab:"로그인 화면 요청",
    pr:"HTTPS", po:"443", fw:"F1", info:"GET /login", d:"브라우저가 로그인 화면을 요청합니다." },
  { n:2, ph:"A", k:"s", f:"proxy", t:"browser", l:"br_px", lab:"로그인 화면",
    pr:"HTTPS", po:"443", fw:"F1", info:"200 OK (text/html)", d:"로그인 화면을 돌려줍니다." }
];
var PH = { A:"처음 연결할 때" };
var SC = [
  { id:"A", t:"처음 연결할 때", d:"한 줄 설명", st:S, tp:"web", grpT:"웹", desc:"흐름 개요 문단" }
];
```

| 단계 속성 | 뜻 |
|---|---|
| `n` | 번호. 요청과 응답에 각각 번호를 매김(같은 번호를 쓰지 않음) |
| `ph` | 흐름 단계(`PH`의 키). 바뀌면 목록에 단계 제목이 나옴 |
| `k` | `q` 요청(코랄 실선) / `s` 응답(보라 점선) |
| `f`, `t` | 보내는 노드, 받는 노드 |
| `l` | 지나가는 선(`TOPO.L`의 키) |
| `lab` | 단계 이름(목록·말풍선) |
| `pr`, `po` | 프로토콜, 포트 |
| `fw` | 방화벽: `FWR` 번호(여러 개면 `"F11 · F2"`), `IN`(같은 VM), `"인터넷"`, `"—"`(같은 프로세스) |
| `info` | 짧은 내용(패킷 데이터가 없을 때 대신 씀). HTML로 들어가므로 꺾쇠는 `&lt;` `&gt;`로 씀 |
| `d` | 단계 설명. HTML로 들어감(`<code>` 등, 꺾쇠 글자는 `&lt;` `&gt;`) |

| 흐름 속성 | 뜻 |
|---|---|
| `id` | 흐름 id |
| `t`, `d` | 목록의 제목과 한 줄 설명 |
| `st` | 단계 배열 |
| `tp` | 구성도 이름(`TOPO`의 키). 필터 탭도 이 값으로 나눔 |
| `grpT` | 목록에서 이 흐름부터 시작하는 묶음 제목 |
| `desc` | 흐름 개요 문단. HTML로 들어감 |

`d`·`info`·`desc` 말고는 모두 글자 그대로 보입니다(구성도 이름, 단계 이름, 구간, 방화벽 규칙, 패킷). 그런 곳에는 `<도메인>`을 그대로 씁니다.
| `g`, `multi` | 묶음 제목, 여러 `ph`가 섞였는지. 엔진이 계산함(`g`는 앞쪽에서 가장 가까운 `grpT`) |
| `groups`, `gi` | 구간 목록, 단계별 구간 번호. 엔진이 `GR`로 계산함 |

엔진이 계산하는 값을 데이터에 직접 적으면 엔진은 적힌 값을 그대로 씁니다.

## 구간

```js
var GR = { A: [ { r:[1, 2], t:"로그인 화면 열기", d:"한 줄 설명" } ] };
```

`GR[ph]`는 흐름 단계 `ph`의 구간 목록이고, `r`은 그 구간에 드는 단계 번호의 처음과 끝입니다. 엔진은 흐름마다 단계 번호로 구간을 찾아 `sc.groups`와 `sc.gi`를 만듭니다. 어느 구간에도 들지 않는 단계가 이어지면 `PH`의 이름으로 한 구간이 됩니다. `GR`을 쓰지 않으면 흐름 단계(`ph`)마다 구간이 하나씩 생깁니다.

## 패킷

```js
var PKT = { web: { 1:["HTTPS", "GET /login HTTP/2"], 2:["HTTPS", "HTTP/2 200 (text/html)"] } };
```

`PKT[tp][단계 번호] = [프로토콜, 내용]`. 프로토콜이 `META.inproc`(기본 `JVM`, `JDBC`)에 있으면 "같은 프로세스 안의 호출"로 표시합니다. 내용은 실제 요청줄·응답·SQL을 쓰고, 예시 주소·비밀값은 넣지 않습니다(`<도메인>` 같은 자리표시를 씀).

## 언어

화면 글자(버튼, 머리, 범례 등)는 엔진이 한국어와 일본어로 갖고 있습니다. 데이터 글은 언어마다 번역 파일 하나에 원문을 키로 적습니다.

```js
// ja.js
TR.ja = {
  "로그인 화면": "ログイン画面",
  "브라우저가 <code>https://app.&lt;도메인&gt;/</code>을 엽니다.": "ブラウザが<code>https://app.&lt;ドメイン&gt;/</code>を開きます。"
};
```

- 키는 데이터에 적은 원문과 글자 하나까지 같아야 합니다. 원문을 고치면 번역 파일의 키도 고칩니다. 번역이 없는 글은 원문이 그대로 나옵니다.
- 번역하는 글: 노드의 `nm`·`rl`·`full`·`al`·`sn`, 그룹 `t`, 시퀀스 머리 `sr`, `FWR`의 `r`·`sh`·`d`, `META.fwNet`·`fwIn`·`filters`의 이름, `PH`, 흐름의 `t`·`d`·`desc`·`grpT`, 단계의 `lab`·`d`·`info`·`pr`·`po`, 구간의 `t`·`d`, 패킷의 프로토콜과 내용, `data.json`의 `title`·`subtitle`.
- 구분용 값(`fw`, `k`, `ph`, `id`, `tp`, 노드 id)은 번역하지 않습니다.
- `d`·`info`·`desc`는 번역도 HTML입니다(꺾쇠는 `&lt;` `&gt;`). 패킷 내용은 글자 그대로 보이므로 `<ドメイン>`처럼 씁니다.
- 번역이 빠진 글: `python tests/untranslated.py <빌드한 HTML> ja <출력 JSON>`. `smoke.py`도 언어마다 빠진 번역과 화면에 남은 원문을 알려 줍니다.
- 처음 고르는 언어: 주소의 `?lang=ja` → 저장한 언어(언어 메뉴로 고른 값) → 브라우저 언어 → 원문 언어.
- `langs`에 `ja`가 있으면 일본어 글꼴(M PLUS 1 Code)을 쓰인 글자만큼 넣습니다. 일본어 화면에서는 가나·한자를 이 글꼴로 그립니다(한국어 글꼴의 한자는 모양이 다릅니다).
- 일본어·한국어가 아닌 언어도 `langs`와 번역 파일로 넣을 수 있지만, 엔진의 화면 글자 표(`UI_TR`)에 그 언어를 더하기 전까지 버튼과 머리 글자는 한국어로 나옵니다.

## 색

화면의 색은 모두 엔진의 CSS 변수로 정해져 있습니다(라이트는 `:root`, 다크는 `[data-theme="dark"]`). 색을 바꾸려면 CSS 파일을 데이터 폴더에 두고 `data.json`의 `css`에 적습니다. 엔진 CSS 뒤에 들어가므로 같은 변수를 다시 적으면 덮어씁니다.

```json
{ "css": ["theme.css"] }
```

```css
/* theme.css */
:root { --btn:#1D4ED8; --accent:#2563EB; --req:#F59E0B; --resp:#8B5CF6; }
[data-theme="dark"] { --btn:#3B82F6; --accent:#60A5FA; }
```

| 변수 | 쓰는 곳 |
|---|---|
| `--bg`, `--panel`, `--panel-2` | 바탕, 칸, 마우스를 올린 곳 |
| `--line`, `--rule`, `--rule-2` | 칸 테두리, 구분선, 빈 진행 막대 |
| `--ink`, `--ink-strong`, `--ink-2`, `--muted`, `--faint`, `--fainter` | 글자(진한 것부터 옅은 것까지) |
| `--btn`, `--accent`, `--tint` | 주 단추와 머리 로고, 강조, 지금 단계의 바탕 |
| `--req`, `--req-ink`, `--on-req` / `--resp`, `--resp-ink` | 요청(선, 글자, 요청 색 위의 글자) / 응답 |
| `--ok`, `--now` | 끝난 단계·흐름, 보던 중인 흐름 |
| `--sel-bg`, `--sel-bd`, `--chev-on` | 고른 흐름의 바탕, 왼쪽 막대, 펼침 표시 |
| `--link`, `--seen`, `--grid`, `--grp`, `--tile`, `--tile-bd` | 구성도의 선, 지나간 선, 격자, 그룹 상자, 시퀀스 머리 |
| `--iso-*`, `--pad-q`, `--pad-s` | 아이소메트릭 아이콘의 면·선·그림자, 강조된 노드의 바닥 |
| `--shadow`, `--pulse-a`, `--pulse-q`, `--pulse-s`, `--pulse-play` | 언어 메뉴 그림자, 지금 단계와 재생 단추의 맥박 |

`:root`에만 적은 변수는 다크 테마에도 그대로 쓰입니다(파일이 엔진 CSS보다 뒤에 있어서). 다크에서 다른 값을 쓰려면 `[data-theme="dark"]`에도 적고, 라이트에서만 바꾸려면 `:root:not([data-theme="dark"])`에 적습니다. 파일에 `</style`이 있으면 빌드가 멈춥니다.

## 알려진 한계

- 엔진의 화면 글자는 한국어·일본어만 있음(다른 언어는 엔진의 `UI_TR`에 표를 더해야 함)
- 구성도 좌표를 손으로 정해야 함(선이 겹치지 않게 직교 경로로)
