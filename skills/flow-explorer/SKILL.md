# flow-explorer

왼쪽에 흐름 목록, 가운데에 아이소메트릭 구성도(패킷이 노드 사이를 움직이고 카메라가 따라감)와 시퀀스 화면, 오른쪽에 단계 설명(프로토콜·포트·방화벽·실제 패킷)이 있는 탐색기를 만든다. 결과는 글꼴·로고·데이터가 모두 들어간 HTML 파일 하나라서 인터넷 없이 열린다. 화면은 한국어이고, 번역 파일을 더하면 머리의 언어 메뉴로 일본어와 바꿔 볼 수 있다.

프로젝트마다 다른 내용은 **데이터 폴더**에만 쓴다. 엔진(`engine/explorer.html`)은 고치지 않는다. 형식은 [references/data-format.md](references/data-format.md)에 있고, 그대로 빌드되는 예제는 `${CLAUDE_SKILL_DIR}/../../examples/web-oauth`에 있다(nginx → 앱 서버 → PostgreSQL, Keycloak OIDC 로그인).

## 준비

Python 3.10 이상과 `fonttools`, `brotli`, `playwright`(검사용 Chromium 포함)가 필요하다. 없으면 설치 명령(`pip install fonttools brotli playwright`, `python -m playwright install chromium`)을 사용자에게 보여 주고 설치해도 되는지 묻는다.

## 순서

1. **데이터 폴더 위치를 묻는다.** 탐색기에는 내부 구성(구성도, 방화벽 규칙, SQL)이 담긴다. 프로젝트 저장소 안에 둘지 밖에 둘지, 결과 HTML은 어디에 둘지 먼저 정한다.
2. **내용을 모은다.** 추측하지 않고 저장소에서 읽는다. 확인하지 못한 포트·경로·순서는 사용자에게 묻는다.
   - 구성도: `docker-compose*.yml`(서비스, 포트, 네트워크, `depends_on`), 쿠버네티스 매니페스트, 리버스 프록시 설정(nginx, Caddyfile, Traefik), Terraform의 보안 그룹. 노드, 그룹(VM·망·프로세스), 선을 정한다.
   - 흐름: 설계 문서, 라우트·컨트롤러, 다른 서비스 호출, E2E 테스트(실제 순서가 잘 드러난다). 사용자가 보는 시나리오마다 흐름 하나를 만들고, 전부 이은 "전체 흐름"을 맨 앞에 둔다.
   - 패킷: 단계마다 실제 요청줄·주요 헤더·응답·SQL. SQL은 코드와 같은 문장을 쓴다. 비밀값, 토큰, 실제 주소, 고객 이름은 `<도메인>`, `…` 같은 자리표시로 바꾼다.
   - 방화벽: 망이나 VM 경계를 넘는 선마다 규칙 번호를 붙이고, 여는 통신과 이유를 `FWR`에 적는다.
3. **데이터를 쓴다.** 예제 폴더를 복사해 고치는 것이 가장 빠르다. 구간은 흐름마다 4~6개로 묶는다.
   - 단계 이름(`lab`)은 짧은 명사구로 쓰고 자세한 내용은 `d`에 쓴다. 시퀀스 화면에서 이웃한 두 열 사이를 오가는 단계는 이름이 한글·일본어 전각 기준 6~8자(`col` 110이면 6자, 130이면 8자)를 넘으면 번호 원에 걸린다. 여러 열을 건너는 단계는 더 길어도 된다.
   - `data.json`의 제목은 한글 12자, 부제목은 25자 안팎으로 쓴다. 길면 머리에서 두 줄로 접힌다.
   - 일본어 화면도 필요하면 `data.json`에 `"langs": ["ko", "ja"]`를 넣고 `ja.js`를 `scripts` 끝에 더한다. 한 번 빌드한 뒤 `python ${CLAUDE_SKILL_DIR}/tests/untranslated.py <출력 HTML> ja <목록 JSON>`으로 원문 목록을 뽑아, 그 키를 그대로 써서 `TR.ja`를 채운다(형식은 data-format.md의 "언어").
   - 번역 규칙: 코드, 식별자, SQL, HTTP 줄은 그대로 둔다. 자리표시는 `<ドメイン>`처럼 옮긴다. 일본어와 영문·숫자 사이에 공백을 넣지 않는다. 설명은 です・ます体, 이름과 단계 이름은 짧은 명사구로 쓴다. 일본어 단계 이름은 `〜のリクエスト`가 붙어 한국어보다 길어지기 쉬우니 `取得`·`要求`처럼 줄여 위의 글자 수를 지킨다. 용어는 하나로 정해 끝까지 같은 말을 쓴다.
   - 색을 바꿔 달라고 하면 데이터 폴더에 `theme.css`를 만들고 `data.json`의 `css`에 적는다(변수 목록은 data-format.md의 "색"). 엔진은 고치지 않는다.
4. **구성도 좌표를 잡는다.** 아래 "좌표 규칙"을 지킨다.
5. **로고를 받는다.** `python ${CLAUDE_SKILL_DIR}/fetch_icons.py <데이터 폴더>`. 못 받은 로고는 `이름:다른슬러그`나 `이름=공식 파일 URL`(그 프로젝트의 저장소나 사이트에 있는 로고)로 다시 받는다. 로고는 각 회사의 상표이므로 색과 모양을 바꾸지 않고, 공개 저장소에 올리지 않는다. 로고가 없어도 빌드는 되고, 그 노드의 미니 로고만 빠진다.
6. **빌드한다.** `python ${CLAUDE_SKILL_DIR}/build.py <데이터 폴더> <출력 HTML>`
7. **검사한다.** `python ${CLAUDE_SKILL_DIR}/tests/smoke.py <출력 HTML> <스크린샷 폴더>`가 "통과"를 낼 때까지 고친다. JS 오류, 패킷 누락, 미니 로고와 선·말풍선 겹침, 휴대폰 폭 가로 스크롤을 보고, 언어가 둘 이상이면 언어마다 빠진 번역과 화면에 남은 원문도 본다. 그다음 스크린샷을 직접 열어, 선이 글자를 지나거나 노드·그룹이 겹치지 않는지 확인한다. 스크린샷은 흐름마다 마지막 단계를 보여 주고, 지금 구간과 관계없는 노드와 선은 흐리게 나온다. 스크린샷은 구성도만 찍으므로, 시퀀스 화면은 결과 HTML을 열고 시퀀스 탭으로 바꿔(Playwright라면 `__flow.tab('seq')`) 단계 이름이 번호 원에 걸리지 않는지 따로 본다.
8. **전달한다.** 결과 HTML의 위치를 알려 준다. 엔진을 고쳤다면 `python ${CLAUDE_SKILL_DIR}/tests/equiv.py <예전 빌드> <새 빌드>`로 화면이 바뀌지 않았는지(차이 0) 확인한다.

## 좌표 규칙

- `x`, `y`는 아이콘 가운데다. 선은 아이콘 옆(가운데에서 ±36), 위(−36), 아래(+80, 이름과 역할 글자 밑)에 닿는다.
- 선은 가로·세로로만 꺾는다. 선끼리 교차하거나 겹치지 않게 하고, 노드 이름·역할·그룹 제목 위를 지나지 않게 한다.
- 한 변에서 선 두 개가 나가면 20 이상 띄운다. 아이콘 오른쪽 위는 미니 로고 자리이므로 선을 내지 않는다.
- 노드는 가로 220, 세로 200 이상 띄운다(이름이 길면 더).
- 그룹 상자는 안의 노드와 글자보다 30 이상 크게 잡고, 왼쪽 위 제목 자리를 비운다. 그룹 안의 그룹은 바깥 테두리에서 30 띄운다.
- `vb`는 모든 노드, 글자, 그룹, 미니 로고를 담고 사방에 20쯤 여백을 둔다.
- 시퀀스 너비는 `60 + 열 수 × col`이다. 패널(1440px 화면에서 약 690px)보다 넓으면 가로로 스크롤되므로, 열이 적으면 `col`을 줄인다(5열이면 120).

## 규칙

- 자료는 그 자체로 완성되어야 한다. 화면에 출처, 커밋, 다른 파일 안내, 만든 방법 같은 문구를 넣지 않는다.
- 요청과 응답에 각각 번호를 매긴다(시간 순, 같은 번호를 쓰지 않음). 요청은 노랑 실선, 응답은 보라 점선으로 엔진이 그린다.
- 방화벽은 번호만 쓰지 않고 `FWR`에 여는 통신과 이유를 적는다. 같은 VM 안은 `IN`, 같은 프로세스 안은 `"—"`, 우리 망 밖은 `"인터넷"`.
- 같은 프로세스 안의 호출은 패킷이 아니므로 패킷 프로토콜을 `JVM`(또는 `META.inproc`에 적은 이름)으로 쓴다.
- 데이터 파일은 값만 선언한다. 엔진과 같이 쓰는 이름은 `var`로 선언한다(`const`·`let`은 엔진의 선언과 부딪힌다).
